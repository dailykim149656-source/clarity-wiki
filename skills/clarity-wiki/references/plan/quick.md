# 기획: Socratic Quick (5~10분)

**언제**: 시간제한 과제, 처음 보는 README, 아이디어 즉석 기획, 짧은 요구사항 정리.

## 7분 타임박스 예시

1. **0~2분, 자료 확인**: README, 제공 파일, 코드를 먼저 읽고 목적과 완료 조건을 파악한다.
2. **2~4분, 모호성 선별**: 전제가 사실인지, 예외/데이터/승인/보안 중 무엇이 결과를 뒤집는가? 영향 큰 질문 최대 3개만 선택한다.
3. **4~6분, 질문과 가정**: 자료에서 답을 찾지 못한 핵심 질문만 제안한다. 외부 발송은 사용자가 허용한 경로와 범위를 따른다. 미답변은 가정과 영향으로 남긴다.
4. **6~7분, 실행 계약**: 채택한 가정, 성공 조건, 테스트 케이스, 보류할 항목을 짧게 기록한다.

## 소크라테스 질문의 규칙

- 처음에 답이 정해진 유도 질문을 하지 않는다.
- 질문마다 `왜 이 결정을 바꾸는가?`를 붙인다.
- 이미 문서에 있는 내용을 다시 묻지 않는다.
- 다른 기능의 우선순위나 정책을 바꾸는 질문만 사용자나 실무자에게 묻는다.
- 답변 불가능한 것은 조용히 임의 결정하지 말고 가정과 위험을 남긴다.
- 대답이 필요 없는 사소한 부분은 보수적인 기본값과 근거를 적고 진행한다.

## 출력: 6행 요약

- 목적:
- 현재 파악한 근거:
- 가장 중요한 불확실성(최대 3):
- 담당자에게 물을 질문(최대 3):
- 성공 조건과 직접 검증 방법:
- 보류 또는 중단해야 할 조건:

추가 명세가 필요하면 [실행 계약](contract.md) 문서를 읽는다.
