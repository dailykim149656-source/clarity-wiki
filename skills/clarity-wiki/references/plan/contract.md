## 구현하면서

- 작업을 나눌 때마다 `요구사항 ID → 구현 위치 → 테스트/근거`를 연결한다.
- 검증 실패, 미완성, 보류를 성공이라고 쓰지 않는다.
- AI의 검사 결과만으로 충분한지 판단한다. 높은 위험의 핵심 수치는 사람의 직접 확인으로 별도 남긴다.
- 확정되지 않은 원인은 추정으로만 표시하고 실무자 확인 대상에 넣는다.

## 종료 시

**완료**: 통과 조건을 전부 확인하고 근거를 남김.
**부분 완료**: 미완성의 영향과 대체 방안을 명시함.
**보류**: 핵심 근거가 없거나 승인되지 않았음을 명시함.

추상적인 '잘 작동해야 함'은 검증 기준이 아니다. 기존에 허용된 작업은 반복 승인 없이 진행하고, 승인 범위 밖의 외부 조치에 필요한 결정만 확인한다.
