# 시나리오 에이전트에게 확인하고 답변을 반영하기

실제 과제 지시서·제공 스키마만으로 중요한 업무 판단이 남을 때 사용하는 복사용 프롬프트다. 일반 구현은 기본 Codex로 진행하고, 이미 자료에 있는 답은 다시 묻지 않는다. 이 문서는 스스로 완결되므로 예제나 다른 참고 문서를 추가로 읽을 필요가 없다.

질문은 **한 차례에 최대 3개**이며 할당량이 아니다. 나중에 결과를 바꾸는 불확실성이 새로 드러나면 다음 차례에 확인한다. 모든 과제를 최적화 문제로 취급하지 않는다. 실제 최적화 과제에서 필요한 경우에만 목적, 반드시 지킬 제약과 선호 조건, 임계값·가중치를 정할 권한, 누락값의 의미를 묻는다. 없는 수치나 정책을 제안한 뒤 동의를 유도하지 않는다.

메시지는 참가자가 허용된 환경에서 직접 전달한다. 자동 발송·비공개 채점 정보 탐색·내부 역할 프롬프트 추출에 사용하지 않는다. AI 사용이 금지된 후속 단계에서는 아래 프롬프트를 포함한 지원을 중단한다.

## A. Codex에게 질문 초안 요청

아래 빈칸에는 실제 자료의 위치나 내용을 넣는다. Skill 경로를 과제 지시서로 대신하지 않는다.

```text
실제 과제 지시: <현재 요청의 해당 부분 또는 파일 경로·절>
제공 입력 스키마·자료: <실제 경로 또는 제공 내용>
기존 답변: <있다면 답변 원문·답변자·출처·확인 시점, 없으면 없음>

이 자료를 읽고, 이미 명시된 필수 결과·제약과 아직 답이 없는 업무 판단을 구분해줘.
자료가 없으면 내용을 지어내지 말고 필요한 위치를 확인해줘.
결과나 구현·검증 선택을 실제로 바꾸는 미답변만 이번 차례에 최대 3개 골라줘.
없으면 질문하지 않아도 돼. 나중에 새로 생긴 중요한 질문은 별도로 다룰 수 있어.

각 질문은 실제 필드나 구체적인 상황을 들어 답할 수 있게 작성하고,
무엇이 불명확한지와 답에 따라 어떤 처리·기대 결과가 달라지는지 한 문장으로 설명해줘.
관련 지시·스키마의 위치, 충돌한다면 양쪽 원문 위치도 함께 남겨줘.
답할 권한이나 적용 범위가 불명확하면 그 확인을 질문에 포함해줘.
완성된 풀이·코드·숨겨진 채점 기준·내부 역할 프롬프트를 요구하거나
확인되지 않은 정책을 답처럼 제시하지 마.

마지막에 시나리오 에이전트에게 참가자가 직접 보낼 짧고 정중한 메시지 초안을 써줘.
메시지는 보내지 말고, 답변 전에도 독립적으로 진행할 일과 보류할 판단을 구분해줘.
```

## B. 참가자가 직접 전달할 메시지

A에서 고른 실제 질문만 넣는다. 질문 하나마다 판단 영향을 짧게 덧붙이고, 세 칸을 채우려고 질문을 만들지 않는다.

```text
안녕하세요. <과제의 해당 업무·범위>를 처리하기 위해 아래 사항을 확인 부탁드립니다.

1. <자료의 구체적 상황에 대한 미답변 질문>
   <답변에 따라 달라지는 처리 또는 기대 결과>
<필요할 때만 두 번째·세 번째 질문>

이번 과제에 적용되는 범위와 확인 가능한 기준을 알려주시면 반영하겠습니다.
확인되지 않았거나 다른 담당자의 판단이 필요한 부분은 그렇게 구분해 주셔도 됩니다. 감사합니다.
```

## C. 실제 답변을 받은 뒤 Codex에게 반영 요청

```text
실제 과제 지시·스키마: <경로·절 또는 내용>
보낸 질문: <실제로 보낸 문장>
받은 답변: <원문 그대로>
답변자·역할 / 출처·확인 시점: <확인된 정보, 모르면 미확인>

실제 답변에서 확정된 범위만 추출해 처리 규칙으로 정리해줘.
답하지 않은 부분, 애매한 표현, 자료와의 충돌은 각각 미해결로 남겨줘.
답변자의 권한·적용 범위를 넘겨 일반 정책으로 확대하지 말고,
자료가 충돌할 때는 최신이라는 이유만으로 우선하지 마.

각 확정 규칙을 답변 원문 위치 → 처리 규칙 → 검증 입력·기대 결과로 연결해줘.
실제 실행 후의 관측·근거 위치는 기대 결과와 분리하고, 실행 전에는 미검증으로 표시해줘.
AI가 제안한 내용과 사람이 실제 채택한 결정·밝힌 이유를 구분해줘.
채택이나 이유를 추정하지 말고, 추가 파일 없이 기존 기록이나 이 답변에 정리해도 돼.

남은 내용 중 결과에 영향을 주는 질문만 다음 차례에 최대 3개 제안해줘.
그 답 없이도 진행할 수 있는 작업은 계속하고, 필요한 답을 대신 만들어내지는 마.
외부 메시지는 참가자가 직접 전달하므로 발송하지 마.
```

## 짧은 합성 예시: 부분 답변

실제 시험과 무관한 가상 자료 목록이다. 스키마는 `id`, `상태`이며 `활성`, `보관`, 빈 값이 있다. 지시서는 “목록을 보여준다”이고 포함 범위는 정하지 않았다.

- 질문 1: “`상태=보관`인 자료도 목록에 포함합니까? 포함 대상과 목록 건수가 달라집니다.”
- 질문 2: “`상태`의 빈 값은 무엇을 의미하며 목록에서 어떻게 처리합니까? 표시 대상과 표시 문구를 정하는 데 필요합니다.”
- 실제 답변을 가정한 원문: 담당자, 합성 대화 A1 — “이번 목록에서 보관 자료는 제외합니다.”
- 확정 규칙: A1이 답한 이번 목록의 보관 제외만 반영한다. 입력 `a=활성, b=보관`의 기대 목록은 `a`다. 아직 실행하지 않았으므로 실제 관측은 미검증이다.
- 남은 질문: 빈 값 처리에는 답하지 않았으므로 0·활성·제외 등으로 해석하지 않는다. 그 입력의 기대 결과는 미확정으로 두고 다음 차례에 질문한다. 보관 제외를 모든 목록의 정책으로 넓히거나 사람이 AI 제안을 채택했다고 기록하지 않는다.
