# 작업 기록 양식

작업 지시나 사용자가 기록을 요구했거나 기존 기록을 갱신할 때 사용한다. 모든 작은 작업에 별도 기록 파일이 필요한 것은 아니다. 프로젝트에서 선택한 파일 하나에 필요한 항목만 기록하며, 이 이름은 제출 파일명 규정이 아니다.

새 요구사항·답변·결정, 실행·검증 결과, 차단 원인 등 의미 있는 변화가 생기면 같은 기록을 갱신한다. 아래 빈칸은 실제 근거로 채우며, 수행하지 않은 확인을 완료로 기입하지 않는다.

## 원래 요구사항

실행 전에 모든 필수 산출물을 출처·완료 기준과 함께 정리한다.

| ID | 원래 요구 내용·필수 산출물 | 요구 주체·원문 위치 | 완료 기준 | 대표 입력·기대 동작 | 상태 |
|---|---|---|---|---|---|

상태: `verified` 실제 기준 확인, `unverified` 미실행·미확인, `blocked` 진행 차단. 상태를 뒷받침하는 근거를 아래에 연결한다.

## 우선 확인할 실패 조건

| 관련 요구사항 ID | 우선 확인할 실패 조건·출처 | 실패 영향·우선 확인 이유 | 검증 입력·기대 동작 | 상태 |
|---|---|---|---|---|

실패했을 때 영향이 큰 조건부터 확인하되, 모든 필수 산출물과 필요한 검증을 유지한다. 조건과 영향은 작업 지시·실제 자료에서 확인하고, 근거 없는 비용·임계값·정책·승인 조건을 가정하지 않는다. 미확인 내용은 `미확인`으로 남긴다.

## 이해관계자의 실제 답변

| 관련 ID·답변 ID | 답변자·역할 | 실제 답변 | 출처·확인 시점 | 확정 범위·미해결 질문/충돌 |
|---|---|---|---|---|

답변받지 않은 내용은 `미확인`으로 남긴다. AI의 추정으로 담당자나 요구 주체의 답변을 만들지 않는다. 부분 답변은 확인된 범위만 옮긴다.

| 관련 요구사항·답변 ID | 확정된 처리 규칙 | 검증 입력 | 기대 결과 |
|---|---|---|---|

실제 관측과 근거는 아래 실행·확인에 같은 ID로 연결한다. 별도 파일을 추가할 필요는 없다.

## AI 제안과 사용자 결정

| 관련 ID | AI 제안 | 제안 근거 | 확인할 내용 |
|---|---|---|---|

| 관련 ID | 사용자가 명시한 결정 | 사용자가 실제 밝힌 이유 | 출처·확인 시점 |
|---|---|---|---|

AI 제안은 사용자 결정으로 취급하지 않는다. 사용자 결정이 없으면 `미확인`, 사용자가 이유를 밝히지 않았으면 이유는 `미확인`으로 남긴다. AI가 제안한 이유를 사용자의 이유로 옮기지 않는다.

## AI 자율 판단·가정·남은 질문

| 관련 ID | AI가 스스로 판단·실행한 내용 또는 가정 | AI의 이유와 근거 | 미확정 내용과 영향 |
|---|---|---|---|

허용된 범위에서 AI가 자율적으로 수행한 작업은 사용자 결정과 구분한다. 기존 자료로 해결되지 않으며 결과를 바꾸는 질문만 한 차례에 최대 3개를 기록한다. 이후 새로 드러난 중요한 불확실성은 다음 차례에 확인하며, 총 질문 수의 상한으로 취급하지 않는다.

## 실행·확인

| 요구사항 ID·확인한 실패 조건 | 실제 검증 방법·명령 또는 수동 절차 | 입력·산출물·코드 버전/해시 | 관찰한 결과·값·종료 코드 | 근거 파일·위치 | 실제 검증 수행자(AI/사람·이름)·시각 | 현재 상태 |
|---|---|---|---|---|---|---|

파일 생성만으로 검증 완료가 되지 않는다. 실제 검증 근거가 없으면 `verified`로 표시하지 않는다. AI가 실행한 검증과 사람이 직접 확인한 검증을 구분하고, 사람이 확인하지 않았다면 사람 검토 완료로 적지 않는다. 명령을 실행하지 않았다면 명령 결과를 채우지 않는다.

미실행·미확인은 `unverified`로 남기고 필요한 확인을 적는다. 실행을 막는 조건이 있으면 `blocked`로 남기고 차단 원인과 해소 조건을 적는다. 요구사항·입력·산출물·코드가 바뀌어 기존 검증이 유효하지 않으면 관련 항목을 `unverified`로 돌리고 해당 시나리오를 다시 실행한다. 실패 후 수정했을 때도 새 결과와 근거를 연결한다. 해시를 저장할 때는 검증에 사용한 입력과 코드도 포함한다.

## 결과와 남은 일

- 확인한 결과와 연결된 요구사항 ID·실패 조건:
- 실패·미검증·차단 항목과 영향:
- 다음 행동과 필요한 결정:

진행 점검을 요청받으면 이 기록과 실제 실행 근거를 바탕으로 현재 단계, 변경·결정, 수행한 검증과 결과, 미확인·차단 사항, 다음 행동을 5줄 이내로 답한다. 새 근거가 없으면 검증 진척을 덧붙이지 않는다.

자동 구조 점검이 필요할 때만 [manifest 안내](../references/local-checks.md)를 사용한다. 검사 통과와 실제 요구사항 충족은 별도로 판단한다.
