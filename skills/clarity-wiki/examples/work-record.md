# 작업 기록 양식

프로젝트에서 선택한 파일 하나에 필요한 항목만 기록한다. 이 이름은 제출 파일명 규정이 아니다. 아래 빈칸을 실제 관찰로 채우며, 수행하지 않은 확인을 완료로 기입하지 않는다.

## 목적과 근거

- 목표·범위:
- 원자료 위치·버전·확인 시점:
- 필수 산출물과 실제 요구된 파일명:

## 요구사항

| ID | 원문 위치 | 완료 기준 | 검증 시나리오·입력 | 상태 |
|---|---|---|---|---|

상태: `verified` 실제 기준 확인, `unverified` 미실행·미확인, `blocked` 진행 차단. 상태를 뒷받침하는 근거를 아래에 연결한다.

## 결정·가정·질문

| 결정 또는 가정 | 채택·기각 이유와 근거 | 확인 주체 | 미확정 내용과 영향 |
|---|---|---|---|

기존 자료로 해결되지 않으며 결과를 바꾸는 질문만 최대 3개를 기록한다.

## 실행·확인

| 요구사항 ID | 실제 명령 또는 수동 절차 | 입력·코드 버전/해시 | 관찰한 값·종료 코드 | 근거 파일·위치 | 수행 주체·시각 |
|---|---|---|---|---|---|

명령을 실행하지 않았다면 명령 결과를 채우지 않는다. 실패 후 수정했다면 관련 시나리오를 다시 실행하고 새 근거를 연결한다. 해시를 저장할 때는 검증에 사용한 입력과 코드도 포함한다.

## 결과와 남은 일

- 확인한 결과와 연결된 요구사항 ID:
- 실패·미검증·차단 항목과 영향:
- 다음 행동과 필요한 결정:

자동 구조 점검이 필요할 때만 [manifest 안내](../references/local-checks.md)를 사용한다. 검사 통과와 실제 요구사항 충족은 별도로 판단한다.
